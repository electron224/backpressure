## Generic preset contract (only infra)
`labPreset: { id: string; topology: { nodes: { id, kind: 'lb'|'service', config }[]; edges: {from,to}[] }; controls: LabControl[]; metrics: string[]; challenges: {id,text,verdict}[] }`.
`LabControl = { id, label, kind: 'select'|'slider', options?: string[], min?: number, max?: number, def: string|number }`.
Island interpreter rules:
- Service nodes built from their own config (serviceMs/concurrency/queueLimit).
- `lb` node backends come from topology edges (no hardcoded fast/slow).
- `select` controls bind named params (strategy); `slider` controls bind numerics (rps, serviceMs).
- Comparison runs the preset twice with one control flipped (LB: strategy; SPOF/scaling: topology variant).
- Unknown node kind or control kind → dev-throw with file + id; never silent skip.
- kill-node chaos on a single-node preset yields all-errors — surfaced as the narrated lesson, not a crash.

## Tier 1 presets (lb/service primitives only)
- `single-point-of-failure` (proof): single service vs LB+2 replicas. Challenge: survive kill-node with zero errors (replicated passes, single all-fails).
- `latency-and-throughput`: single service, RPS + serviceMs sliders. p99 cliff past capacity (~concurrency/serviceMs), throughput flatlines. Challenge: find the RPS where p99 exceeds 150ms.
- `vertical-vs-horizontal-scaling`: fat service (concurrency 8) vs LB+4 thin (concurrency 2) under same load. Challenge on p99 per config.
- `statelessness`: sticky (fixed single pick) vs least-connections under kill-node; sticky drops in-flight, stateless re-routes. Strategy select; Learn names the sticky-session smell.
- `back-of-envelope-estimation`: predict-then-reveal as the lab — estimate QPS/storage/bandwidth from given DAU, run to check. Numeric-tolerance challenges via gradePrediction.

## Testing

## Risks

- Estimation without a sim feels canned → the runs ARE the check (predict, then reveal actual).
